# ADR-0025: The crate is a library; the CLI is a thin wrapper over it

## Table of Contents

- [Status](#status)
- [Context](#context)

## Status

Accepted (2026-07-28).

## Context

Until now the crate was a binary only: every module lived under
`src/main.rs`, and the sole way to reach the extraction logic was to run
the executable and read its JSON. That works for the existing consumer,
the [`markdown-org-vscode`](https://github.com/VitalyOstanin/markdown-org-vscode)
extension, which spawns the binary.

A second consumer cannot. An Android application may not spawn
processes: the platform ships no writable executable directory that also
permits execution, and even where a bundled binary can be launched the
practice is fragile across vendors and API levels. Such a consumer has
to call the extraction in-process, which means the logic must be
reachable as a Rust library — from there, `uniffi` can generate the
Kotlin bindings.

The obstacle was not the logic itself but its entanglement with argument
parsing. `scan_files` took `&Cli`, so a caller had to construct a clap
type to scan a directory. Two constants used by the parser
(`RU_WEEKDAY_MAPPINGS`) and by the timestamp extractor lived in
`cli.rs`, which pulled clap into modules that have nothing to do with a
command line.

An alternative was considered and rejected: keep the binary and have the
Android app ship it. It fails on the process restriction above, and it
would force the JSON serialise/parse round trip on every scan for data
that is about to be rendered by the same process.

## Decision

### `src/lib.rs` is the crate's real surface

The library owns everything except argument parsing and byte output:
`agenda`, `clock`, `error`, `holidays`, `locale`, `parser`, `render`,
`scan`, `timestamp`, `types`. A flat facade re-exports the names an
embedder needs, while the modules stay public so anything not
re-exported is still reachable without waiting for a release.

The pipeline is two independent steps, so a caller can scan once and
build several agendas from the result:

1. `scan_directory(dir, &ScanOptions, Option<&AtomicBool>) -> ScanOutcome`
2. `filter_agenda(tasks, scope, dates, tz, …) -> AgendaOutput`

### Scanning takes options, not a `Cli`

`ScanOptions` carries the four values the walk needs (`glob`,
`max_tasks`, `absolute_paths`, `locale`) and implements `Default`, so
`ScanOptions::default()` is a working configuration. The interrupt flag
is `Option<&AtomicBool>`: the binary installs signal handlers and passes
`Some`, an embedded caller with no signals passes `None`.

### clap stays in the binary

`cli.rs` and `format.rs` are modules of `src/main.rs`, not of the
library. Nothing in the library depends on clap. The weekday tables
moved to `src/locale.rs` because the parser and the timestamp extractor
need them; the `--locale` validator in the binary remains the single
place that rejects an unknown locale.

### The binary keeps its behaviour

`src/main.rs` parses arguments, installs signal handlers, calls the two
library functions, renders and writes. Exit codes, stderr summaries and
the JSON schema are unchanged — this is a refactoring, and the existing
integration tests over the executable are what proves it.

### The library documents itself

`#![warn(missing_docs)]` is set in `lib.rs`. Items that were previously
private and undocumented are now public API and carry documentation,
including the ones generated by `build.rs`.

## Consequences

- An embedder links the crate and calls the same code the CLI runs;
  there is no second implementation to keep in step.
- The public surface is now a compatibility obligation. `Task` and its
  fields were already a contract through the JSON schema (ADR-0015); the
  Rust names are one now too.
- `tests/lib_api.rs` covers the library surface directly, so a change
  that breaks an embedder fails without going through the executable.
- Compile times grow slightly: the binary depends on the library rather
  than compiling every module into itself.
- Anything added to a public module from here on needs documentation, or
  the build warns.
